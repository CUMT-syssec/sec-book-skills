# Chapter 4: 静态链接

## Core Idea

静态链接的核心是为输入内容分配输出地址、解析符号，并按重定位记录修正机器指令或数据。错误常出现在这三步的边界。

## Frameworks Introduced

- **两步链接**：先合并相似段并分配空间/地址，再解析符号和应用重定位。
  - When to use：解释 map、地址布局、溢出或错误跳转。
  - How：列输入节；确定输出节布局；建立全局符号；逐条处理重定位。
- **符号解析规则**：用强/弱符号和 COMMON 等规则解决同名候选。
  - When to use：重复定义、意外覆盖、未初始化全局变量冲突。
  - How：枚举所有候选的绑定与大小；不要依赖链接器“碰巧选择”。
- **静态库按需抽取**：归档库中的目标文件只有满足未解析引用时才被拉入。
  - When to use：库里明明有符号却仍 undefined reference。
  - How：按链接器扫描顺序追踪未解析集合；必要时调整顺序或显式成组。

## Key Concepts

- **空间与地址分配**：决定输出节的文件偏移和虚拟地址。
- **符号解析**：把引用关联到唯一可用定义。
- **重定位**：根据最终地址修正原先未知或相对的字段。
- **COMMON**：历史上表达 tentative definition 的机制。
- **ABI**：跨目标文件一致解释调用、名字和数据布局的二进制约定。
- **链接脚本**：显式控制入口、段布局、地址与输出格式。
- **BFD**：binutils 用于统一处理多种目标格式的抽象库。

## Mental Models

- 把链接器看成“约束求解器 + 二进制重写器”。
- 把重定位项看成补丁工单：位置、类型、目标符号和加数共同决定修正结果。
- 把静态库看成目标文件索引，不是运行时加载单元。

## Anti-patterns

- **盲目重复添加 `-l`**：可能掩盖顺序、ABI 或可见性根因。
- **依赖弱符号解决设计冲突**：容易因工具链或链接顺序变化产生静默错误。
- **随意复制链接脚本**：地址、对齐、入口和权限假设可能不适用目标平台。

## Worked Example

两个目标文件分别包含 `main/swap` 与共享变量。先用节头计算合并后的 `.text/.data/.bss` 布局，给函数和变量分配地址；再从符号表把 `swap` 与共享变量引用绑定到定义；最后按照重定位类型修正调用指令和数据地址。若符号能解析但指令修正类型错误，程序仍可链接成功却在运行时跳错位置。

## Key Takeaways

1. 链接成功不等于二进制语义正确。
2. 符号解析决定“是谁”，重定位决定“怎样引用它”。
3. 静态库问题要追踪未解析符号集合和扫描顺序。
4. C++ 跨模块问题必须检查名称修饰与 ABI。
5. map、符号表和重定位表是静态链接排障的核心证据。

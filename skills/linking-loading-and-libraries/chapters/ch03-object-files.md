# Chapter 3: 目标文件里有什么

## Core Idea

目标文件是可检查的结构化契约：它把机器码、数据、符号、重定位和调试信息分区保存，供链接器和装载器继续处理。

## Frameworks Introduced

- **按用途分节**：代码、已初始化数据、只读数据、未初始化数据、符号与字符串分别组织。
  - When to use：解释文件尺寸、内存权限、常量位置或自定义段。
  - How：先看节表，再把源级实体映射到节、符号和重定位记录。
- **符号作为链接接口**：定义和引用通过符号表建立跨模块关系。
  - When to use：未定义、重复定义、可见性或名称修饰问题。
  - How：检查绑定类型、所在节、可见性、名称修饰和引用方重定位。
- **格式同源比较**：ELF 与 PE/COFF 结构不同，但都需要表达内容、名字、地址修正和装载元数据。

## Key Concepts

- **ELF / PE / COFF**：主流目标与可执行文件格式家族。
- **`.text`**：可执行代码。
- **`.data` / `.rodata`**：已初始化可写数据与只读数据。
- **`.bss`**：占用运行时内存但通常不在文件中存储零字节主体的未初始化数据。
- **节表**：描述各 section 的类型、位置、大小和属性。
- **符号表**：记录符号名字、绑定、类型、值和所属节。
- **字符串表**：集中保存节名和符号名。
- **调试信息**：把机器级位置关联回源代码结构。

## Mental Models

- 把目标文件看成“未完成的可执行文件”，未决地址由重定位记录显式表示。
- 把 section 看成链接和分析的逻辑单元，不等同于装载时的 segment。
- 文件大小和运行时占用是两个视图；`.bss` 是典型反例。

## Anti-patterns

- **只查字符串判断符号是否可链接**：名字出现不代表它是可见定义。
- **将 section 与 segment 混用**：会错误解释权限和映射。
- **跨 C++ 编译器直接假设符号名一致**：名称修饰和 ABI 可能不同。

## Worked Example

编译一个含全局已初始化变量、未初始化变量、字符串常量和函数的源文件。用节表观察机器码进入 `.text`，初始化变量进入 `.data`，字符串常量进入只读区域，未初始化变量由 `.bss` 描述；再从符号表确认每个实体的绑定和所属节。这个实验把源级声明转换为可验证的文件结构。

## Key Takeaways

1. 目标文件同时服务编译器、链接器、调试器和后续装载。
2. 分节让权限、复用、布局和零初始化可分别处理。
3. 符号表是跨模块契约，字符串表只是名字存储。
4. 诊断链接问题时，节表、符号表和重定位表必须联读。

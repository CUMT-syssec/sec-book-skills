# Chapter 11: 运行库

## Core Idea

运行库把语言语义和常用服务建立在操作系统接口之上。它负责程序入口、初始化、参数与环境、堆和 I/O、TLS、全局构造/析构以及退出清理；`main` 只是中间的一步。

## Frameworks Introduced

- **启动链模型**：`OS/loader → entry → CRT init → constructors → main → destructors/atexit → exit`。
  - When to use：程序在 main 前崩溃、全局对象顺序问题、退出阶段崩溃。
  - How：确定真实入口；识别所链接 CRT；枚举初始化/析构表；在边界设置断点或日志。
- **分层 I/O 模型**：语言层 `FILE*`/缓冲建立在文件描述符或句柄及系统调用/API 上。
  - When to use：缓冲、文本换行、短读写、句柄继承或性能问题。
  - How：区分用户态缓冲状态、CRT 文件表和内核对象状态。
- **TLS 分层**：编译器、链接器、装载器和运行库共同为线程局部对象提供地址与初始化。

## Key Concepts

- **CRT**：C/C++ 运行库与启动支持。
- **入口函数**：可执行文件声明的第一段用户态启动代码。
- **`argc/argv/env`**：从初始进程状态解析出的参数和环境。
- **`FILE` / fd / HANDLE**：不同抽象层上的 I/O 标识。
- **缓冲 I/O**：运行库减少系统调用并提供文本语义。
- **全局构造与析构**：在 main 前后由运行时遍历注册表执行。
- **`atexit`**：注册正常退出回调。
- **TLS**：每线程独立数据和初始化机制。

## Mental Models

- 把 CRT 看成“语言到操作系统的适配层”，它既提供便利也定义 ABI。
- 把 `fread` 看成调用轨迹而非单函数：参数检查、锁、缓冲、换行转换、系统 API。
- 把全局对象生命周期看成跨编译单元的初始化图，避免假设未定义顺序。

## Anti-patterns

- **认为 main 是真实入口**：会漏掉启动和退出阶段。
- **混用不同 CRT 分配与释放资源**：堆、FILE 和异常对象可能不兼容。
- **把一次 `fread` 等同一次内核读取**：缓冲和文本转换会改变调用次数与返回行为。

## Worked Example

追踪 `fread`：调用进入 CRT 后先验证参数并获取流锁；若用户态缓冲已有数据则直接复制，否则请求底层 `read/ReadFile` 填充缓冲；文本模式还可能转换换行；最后更新 FILE 状态并返回元素数。出现“系统调用读到了数据但应用返回较少”时，应检查缓冲、元素大小、EOF/错误标志和文本转换层。

## Key Takeaways

1. 程序启动和退出都是运行库协议。
2. 运行库对象不能脱离其所属 CRT 和模块边界管理。
3. 高层 I/O 返回值需要结合缓冲与元素语义解释。
4. TLS 和全局构造依赖编译、链接、装载、运行库协作。
5. 诊断 main 前后问题要从真实入口和终止路径取证。

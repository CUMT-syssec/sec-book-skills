# Chapter 5: Windows PE/COFF

## Core Idea

PE/COFF 是 Windows 工具链在 COFF 家族上的可执行格式实现。理解文件头、节表、符号/调试信息与数据目录，才能把 Windows 二进制问题还原为可检查的结构。

## Frameworks Introduced

- **同源格式映射**：用 ELF 已知概念对照 PE/COFF，而不假设字段一一对应。
  - When to use：跨 Linux/Windows 分析目标文件和可执行文件。
  - How：分别寻找文件标识、目标架构、节表、入口、映像基址、导入/导出、重定位和调试信息。
- **数据目录导航**：PE 可选头中的目录项把分析器引向导入、导出、资源、重定位等表。
  - When to use：定位 DLL 依赖、导出符号、重定位或资源。
  - How：先验证 RVA/size，再通过节映射换算到文件偏移；不要直接把 RVA 当文件偏移。

## Key Concepts

- **PE**：Windows 映像文件格式，EXE 与 DLL 都使用它。
- **COFF**：PE 的目标文件基础和共同祖先。
- **RVA**：相对映像基址的虚拟地址。
- **Image Base**：映像偏好的装载基址。
- **Data Directory**：指向导入、导出、资源、异常、基址重定位等结构的入口集合。
- **Debug Directory**：指向调试信息或相关标识。
- **Section Table**：描述节在文件和内存中的位置、大小与属性。

## Mental Models

- 把 PE 看成“内存映像蓝图”，文件偏移、RVA 和实际虚拟地址是三种坐标。
- EXE 与 DLL 的格式高度相近，关键差别更多在标志、入口语义和导入导出关系。
- 使用目录项先找到结构，再解释结构；不要全文件盲扫字符串。

## Anti-patterns

- **混淆 RVA 与文件偏移**：会读到错误字节。
- **根据扩展名判断格式和角色**：应验证 PE 头和特征标志。
- **只看导入 DLL 名称推断实际绑定**：还需结合导入表、转发和运行时搜索。

## Worked Example

分析一个 PE：从 DOS 头定位 PE 签名，读取 COFF 头确认架构与节数，再从可选头取得 Image Base、入口 RVA 和数据目录。把导入表 RVA 落到包含它的节，用“RVA - 节虚拟地址 + 节文件偏移”换算文件位置，最后枚举导入描述符。这个流程能避免把内存坐标直接用于磁盘读取。

## Key Takeaways

1. PE/COFF 与 ELF 可用共同问题框架比较，但字段语义必须按格式验证。
2. Windows 二进制分析要始终标注所用坐标系。
3. 数据目录是进入 PE 复杂结构的索引。
4. 调试信息和符号信息可能独立存储，缺一不等于二进制不可分析。

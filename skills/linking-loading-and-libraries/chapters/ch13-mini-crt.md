# Chapter 13: 运行库实现

## Core Idea

通过实现 Mini CRT，把入口、参数、堆、I/O、字符串、格式化、退出和部分 C++ 支持串成可运行闭环。重建最小系统是验证底层理解的手段，不是替代成熟运行库的生产方案。

## Frameworks Introduced

- **最小可运行链**：先让入口调用 main 并正确退出，再逐层增加堆、I/O 和语言特性。
  - When to use：学习运行时依赖、构造最小环境或隔离启动问题。
  - How：每一步只增加一个职责；保持明确入口和链接脚本/选项；用可执行测试验证。
- **堆块分裂与合并**：空闲块足够大时分裂；释放时与相邻空闲块合并。
  - When to use：理解最小 malloc/free 实现。
  - Failure mode：缺少对齐、溢出、并发、双重释放和元数据保护，不适合生产。
- **跨平台薄层**：用条件编译把 Windows API 与 Linux syscall 差异限制在少量底层函数中。
- **按语言特性扩展**：C++ new/delete 建立在堆上，string/iostream 建立在内存与 I/O 上，全局构造依赖启动表。

## Key Concepts

- **入口例程**：解析参数、初始化子系统、调用 main、执行退出清理。
- **Mini CRT heap**：在系统提供的地址区间上实现最小分配器。
- **Mini CRT I/O**：把文件和控制台操作映射到 syscall/API。
- **格式化字符串**：把类型化参数转换为输出序列。
- **`new/delete`**：C++ 动态对象分配接口，可复用底层 malloc/free。
- **全局构造/析构**：链接器收集、入口遍历的函数集合。

## Mental Models

- 把运行库能力画成依赖图：入口在根，堆和 I/O 是基础，字符串/流和 C++ 对象语义在其上。
- 每新增一个功能，同时定义初始化、正常使用、错误处理和清理四条路径。
- “能运行”只证明主路径，不证明兼容、线程安全、异常安全或安全加固。

## Anti-patterns

- **把教学运行库用于生产**：缺少现代 ABI、并发、安全和边界处理。
- **一次实现所有能力再调试**：无法定位是哪一层破坏启动链。
- **只测 main 返回 0**：遗漏分配失败、短读写、格式化边界和退出回调。

## Worked Example

第一阶段定义自有入口：取得参数，初始化堆和 I/O，调用 `main`，执行 `atexit` 回调并退出。第二阶段让 malloc 从一块系统提供的区间建立首个空闲块，分配时按需分裂，释放时合并相邻块。第三阶段在最小 syscall/API 包装上实现文件与字符串输出。最后用 `new/delete` 复用分配器，并通过构造函数表在 main 前初始化全局对象。每阶段都用独立小程序验证成功与失败路径。

## Key Takeaways

1. 重建最小运行链能暴露默认工具链替你完成的工作。
2. 初始化顺序和退出清理与主功能同等重要。
3. 分配器正确性需要边界、对齐、合并和错误路径测试。
4. 跨平台差异应封装在最薄的系统接口层。
5. Mini CRT 是教学与诊断工具，不是现代生产运行库。

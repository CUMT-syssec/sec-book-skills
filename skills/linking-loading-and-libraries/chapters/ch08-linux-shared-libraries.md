# Chapter 8: Linux 共享库的组织

## Core Idea

共享库要长期可维护，必须同时管理文件版本、SO-NAME、符号兼容、系统搜索路径、缓存和安装链接；“文件存在”只是可用性的一个条件。

## Frameworks Introduced

- **三级名称模型**：真实文件名、SO-NAME、链接名承担不同角色。
  - When to use：发布多个版本、升级而保持已有程序可运行。
  - How：真实文件包含完整版本；SO-NAME 表达 ABI 主版本；开发链接名供链接期选择。
- **接口兼容判断**：新增兼容接口通常可保持 ABI，删除/改变既有接口或布局通常要求新主版本。
  - When to use：决定是否升级 SO-NAME。
  - How：比较导出符号、参数/返回约定、数据布局和语义；不要只比较源代码能否编译。
- **搜索链诊断**：把链接期搜索与运行时搜索分开。

## Key Concepts

- **SO-NAME**：共享库写入依赖方的 ABI 身份。
- **真实名称**：包含完整版本号的实际文件。
- **链接名称**：通常供开发阶段链接器查找的未版本化名字。
- **符号版本**：让同名符号的多个 ABI 版本共存或被精确要求。
- **`ldconfig`**：维护常用链接和动态链接器缓存。
- **系统路径 / 环境变量 / 配置**：影响运行时库发现。

## Mental Models

- 把共享库升级看成契约迁移，而不是覆盖文件。
- 把 SO-NAME 看成 ABI 主版本主键。
- 把搜索问题拆成“构建时找到了谁”和“运行时实际加载了谁”。

## Anti-patterns

- **直接覆盖同名 `.so`**：可能让旧二进制静默绑定到不兼容 ABI。
- **长期依赖临时环境变量**：部署结果不可复现且可能扩大劫持面。
- **用源代码版本号代替 ABI 决策**：功能版本和二进制兼容版本并非同一维度。

## Worked Example

发布 `libfoo.so.1.2.3` 时，把其 SO-NAME 设为 `libfoo.so.1`，安装 `libfoo.so.1` 指向真实文件，并让开发链接名 `libfoo.so` 指向当前开发版本。兼容修复可替换 `1.x` 真实文件并更新链接；删除符号或改变结构布局时发布 `libfoo.so.2`，使旧程序继续明确依赖主版本 1。

## Key Takeaways

1. 文件名、SO-NAME 和链接名分别服务安装、运行与开发。
2. ABI 不兼容升级必须可与旧版本并存。
3. 符号版本能提供比文件主版本更细的兼容控制。
4. 搜索路径既是可用性机制也是供应链安全边界。
5. 排障时记录最终解析到的绝对路径与 SO-NAME。

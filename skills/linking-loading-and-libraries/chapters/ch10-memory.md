# Chapter 10: 内存

## Core Idea

程序内存问题要分层分析：虚拟地址空间规定可访问区域，栈和调用约定组织函数活动，堆分配器在操作系统提供的区域上管理动态对象。不同层的损坏会产生相似表象。

## Frameworks Introduced

- **内存布局分区**：代码/数据、堆、共享库、栈、内核保留区具有不同来源、增长方向和权限。
  - When to use：段错误、地址空间耗尽、权限异常或 ASLR 分析。
  - How：先看进程映射，再把地址归类；确认映射、权限、生命周期和所有者。
- **调用栈帧模型**：参数、返回地址、保存寄存器和局部变量按调用约定组织。
  - When to use：栈回溯损坏、参数错位、跨语言调用或返回值异常。
  - How：确认目标架构和调用约定；对照调用点与被调函数的栈/寄存器责任。
- **堆块状态机**：分配器将大块地址空间切为占用/空闲块，并通过分裂、合并和空闲结构复用。

## Key Concepts

- **平坦内存模型**：程序以统一线性虚拟地址寻址。
- **栈**：支持函数调用和自动存储期对象的 LIFO 区域。
- **调用约定**：规定参数、返回值、寄存器保存、栈清理和符号命名。
- **堆**：由分配器动态管理的内存区域。
- **`brk` / `mmap`**：Linux 分配器获取地址空间的典型基础机制。
- **空闲链表 / 位图 / 伙伴系统**：管理空闲块的不同策略。
- **TLS**：每线程独立的存储区域。

## Mental Models

- 指针是“地址 + 隐含的映射、权限、对象生命周期和类型约束”。
- 栈损坏常在返回或回溯时暴露，破坏点可能更早。
- 堆分配器优化的是时间、空间碎片、局部性和并发之间的权衡。

## Anti-patterns

- **看到崩溃地址就认定那里是根因**：越界写常在之后的分配/释放才被检测。
- **跨模块假设相同调用约定或堆所有权**：会破坏栈或分配器元数据。
- **用内存总量解释所有分配失败**：连续地址、提交限制、碎片和策略也重要。

## Worked Example

函数声明在一侧按一种调用约定编译，调用方却按另一种约定传参和清栈。函数主体可能读到看似随机的参数，返回后栈指针进一步偏移，崩溃发生在下一次返回。正确诊断是对照汇编中的参数位置、调用后栈调整和保存寄存器，而不是在最后崩溃处修补指针。

## Key Takeaways

1. 先把故障地址落到实际映射和对象生命周期。
2. 调用约定是跨模块 ABI 的核心组成。
3. 栈用于调用组织，堆用于动态生命周期，二者失败模式不同。
4. 堆分配器必须在碎片、速度和并发之间权衡。
5. 内存损坏要寻找首次越界或非法释放，而不是最后一次报错。

# Chapter 7: 动态链接

## Core Idea

动态链接把共享对象的地址分配、符号解析和部分重定位推迟到装载或首次调用，换来代码共享、模块升级和更小的静态产物，同时引入运行时绑定复杂度。

## Frameworks Introduced

- **地址无关代码（PIC）**：避免依赖固定装载地址。
  - When to use：生成可在多个进程或任意基址共享的代码。
  - How：优先使用 PC-relative 引用；对全局数据通过 GOT；对外部函数通过 PLT/GOT；保留必要重定位。
  - Failure mode：文本重定位会迫使修改代码页，损害共享和安全属性。
- **延迟绑定（PLT）**：把外部函数解析推迟到第一次调用。
  - When to use：减少启动时不必要的符号解析。
  - How：首次调用经 PLT 进入解析器，解析结果写入 GOT，后续直接跳转。
- **动态链接器三阶段**：自举、装载依赖、重定位与初始化。
  - When to use：排查程序在 `main` 前失败或依赖绑定异常。

## Key Concepts

- **共享对象**：可被多个程序动态装载的 ELF 对象。
- **PIC**：位置无关代码。
- **GOT**：全局偏移表，保存运行时地址槽。
- **PLT**：过程链接表，为外部函数调用提供跳板。
- **`.interp`**：指定 ELF 解释器/动态链接器。
- **`.dynamic`**：动态链接元数据集合。
- **动态符号表与动态重定位表**：运行时解析所需的精简符号和修正记录。
- **`dlopen/dlsym/dlclose/dlerror`**：显式运行时装载接口。

## Mental Models

- 把 GOT 看成可在运行时填写的地址表，把 PLT 看成调用方的稳定入口。
- 把 lazy binding 看成“第一次付解析成本并缓存结果”。
- 把动态链接问题按“找到对象 → 选择符号 → 应用重定位 → 执行初始化”分段。

## Anti-patterns

- **把动态链接失败都归因于文件缺失**：版本、搜索路径、架构、符号版本和 ABI 同样关键。
- **假设首次调用与后续调用路径相同**：lazy binding 使两者不同。
- **通过固定地址引用共享对象**：与 ASLR、共享映射和重定位目标冲突。

## Worked Example

主程序调用共享库函数时，编译器生成到 PLT 槽的调用。第一次进入该槽时，GOT 尚指向解析路径；动态链接器依据调用槽和符号信息寻找定义，写回真实地址。第二次调用经过同一 PLT 槽但直接跳到已缓存地址。若只在首次调用崩溃，应重点检查解析器路径、重定位和初始化，而不是函数主体。

## Key Takeaways

1. 动态链接用运行时复杂度换共享和可更新性。
2. PIC、GOT、PLT 分别处理代码位置、数据地址和函数调用间接性。
3. `main` 前故障要检查动态链接器自举、依赖和构造初始化。
4. 显式装载要定义句柄生命周期和失败回滚。
5. 绑定结果是搜索策略、符号规则和版本共同作用的产物。

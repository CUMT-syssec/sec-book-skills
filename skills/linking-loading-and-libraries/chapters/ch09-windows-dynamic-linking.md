# Chapter 9: Windows 下的动态链接

## Core Idea

Windows 通过 PE 导入/导出表、IAT、基址重定位和 DLL 装载规则实现动态链接。它与 ELF 共享“运行时解析”目标，但符号导出、地址表和部署习惯不同。

## Frameworks Introduced

- **导入/导出契约**：DLL 显式暴露符号，调用方通过导入描述和 IAT 获得地址。
  - When to use：检查函数为何未导出、导入名不匹配或加载到错误 DLL。
  - How：验证导出名/序号；核对调用方导入表；运行时检查 IAT 实际地址归属。
- **基址冲突处理**：无法使用偏好 Image Base 时，loader 依据基址重定位表修正绝对引用。
  - When to use：解释 rebasing、装载开销或固定基址假设失败。
- **显式装载生命周期**：加载模块、查找函数、调用、释放，每一步都必须检查失败。

## Key Concepts

- **DLL**：使用 PE 格式的动态链接模块。
- **Export Table**：DLL 对外符号与序号。
- **Import Table / IAT**：依赖描述和运行时函数地址槽。
- **RVA / Image Base**：PE 内相对地址与偏好基址。
- **Base Relocation**：映像移动后需修正的位置集合。
- **Rebasing**：调整偏好基址以减少冲突的技术。
- **导出转发**：一个导出把解析转交给另一 DLL 的符号。
- **DLL Hell**：不受控版本、搜索和共享依赖造成的兼容问题。

## Mental Models

- 把 IAT 看成 Windows 调用方的运行时地址表，作用上可与 GOT 的一部分对照。
- 把 DLL 搜索看成确定性解析算法；安全与正确性都取决于候选路径和优先级。
- C++ 接口跨 DLL 时，把运行库、堆所有权、异常和名称修饰纳入同一 ABI 边界。

## Anti-patterns

- **跨 DLL 边界分配、在另一运行库释放**：可能跨越不同堆或 CRT 实例。
- **导出 C++ 类却不固定工具链 ABI**：名称、布局、异常和 STL 实现都可能漂移。
- **只按 DLL 文件名判断加载对象**：应验证绝对路径、签名/版本和实际模块句柄。

## Worked Example

应用导入 `foo.dll!run`。磁盘上的导入表记录 DLL 与函数，loader 按搜索规则找到具体文件，映射 PE，必要时应用基址重定位，再把 `run` 的最终地址写入 IAT。若应用启动失败，应依次验证找到的绝对路径、架构、依赖闭包、导出名/序号和重定位，而不是只复制一个同名 DLL 到程序目录。

## Key Takeaways

1. DLL 和 EXE 都是 PE 映像，角色由头部与导入导出关系体现。
2. IAT 是调用方观察实际绑定结果的关键证据。
3. 基址重定位允许映像在不同地址装载。
4. DLL 兼容性问题本质仍是 ABI、版本和搜索策略问题。
5. 跨 DLL 边界优先使用明确所有权的稳定 C 接口。

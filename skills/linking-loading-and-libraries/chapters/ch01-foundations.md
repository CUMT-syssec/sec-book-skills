# Chapter 1: 温故而知新

## Core Idea

先建立硬件、操作系统、虚拟内存与线程的共同语言，再解释程序为何能被隔离、共享资源并并发执行。底层问题往往不是孤立技巧，而是抽象层之间的契约失配。

## Frameworks Introduced

- **“增加中间层”的万能法则**：用新的抽象层隔离变化和复杂度。
  - When to use：两个系统直接耦合、地址或设备差异泄漏到上层时。
  - How：识别不稳定部分；建立稳定接口；明确映射状态；再检查新层引入的开销与故障模式。
  - Failure mode：把抽象当现实，忽略地址转换、缓存、权限和调度细节。
- **分层计算机系统**：应用、运行库、系统调用、内核、硬件各自承担不同责任。
  - When to use：定位性能瓶颈、权限错误或平台差异。
  - How：从观察到的现象向下追踪到第一处改变语义的边界。

## Key Concepts

- **CPU、内存、I/O 控制芯片**：软件视角下最关键的硬件组成。
- **多任务**：操作系统通过调度让多个程序共享 CPU。
- **虚拟地址空间**：进程看到的独立地址视图，经映射关联物理内存。
- **分段与分页**：将虚拟地址映射到物理资源的两类历史/现实机制。
- **线程**：进程内部共享地址空间但拥有独立执行上下文的执行流。
- **线程安全**：共享状态在并发访问下仍保持约束成立。

## Mental Models

- 把操作系统看作资源管理者和抽象提供者，而不是“运行程序的背景”。
- 把虚拟地址看作名字，物理页看作资源，页表看作名字到资源的动态映射。
- 把线程切换看作保存/恢复执行现场；共享越多，同步责任越大。

## Anti-patterns

- **只在高级框架层排障**：底层映射、权限或调度错误不会因换 API 消失。
- **把地址值当物理位置**：相同虚拟地址可在不同进程映射到不同物理页。
- **默认共享数据天然安全**：可见性、原子性和操作顺序都可能破坏约束。

## Worked Example

程序访问空指针时，先不要把“0”理解为一块损坏的内存。应用给出虚拟地址 0，MMU 查询该进程页表，发现该区域未映射或无权限，CPU 触发异常，内核再把它转换为进程可见的错误。这个路径展示了中间层如何同时提供隔离和诊断信号。

## Key Takeaways

1. 先定位抽象边界，再解释现象。
2. 虚拟化解决隔离与管理，也引入映射和权限状态。
3. 并发问题必须同时考虑共享数据和执行交错。
4. 后续链接、装载和运行库机制都依赖本章的地址空间模型。

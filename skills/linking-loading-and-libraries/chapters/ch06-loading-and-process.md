# Chapter 6: 可执行文件的装载与进程

## Core Idea

现代装载的本质是建立“可执行文件区间到进程虚拟地址区间”的映射，并按需由页错误把内容带入内存，而不是一次性复制整个文件。

## Frameworks Introduced

- **映射优先模型**：先描述虚拟地址布局和权限，再讨论物理页何时出现。
  - When to use：解释 RSS、启动速度、共享页、BSS、缺页或权限错误。
  - How：读取 program headers；确定 segment 的文件区间、虚拟区间、权限和对齐；再对照进程映射。
- **链接视图 vs 执行视图**：section 服务链接，segment 服务装载。
  - When to use：多个 section 为什么共同映射、文件大小为何小于内存大小。
  - How：按相同权限和邻近布局把 section 归入 LOAD segment。
- **按需分页**：页第一次访问时发生缺页，内核再建立或填充映射。

## Key Concepts

- **进程虚拟地址空间**：每个进程独立的地址视图。
- **覆盖装入**：虚拟内存普及前由程序手工复用有限内存的技术。
- **页映射**：以页为单位把文件或匿名内存关联到虚拟地址。
- **Program Header**：描述 ELF 的装载 segment。
- **Page Fault**：访问尚未建立、尚未驻留或无权限页面时的异常。
- **初始栈**：装载器/内核放置参数、环境和辅助信息的启动结构。
- **入口地址**：装载完成后开始执行的位置，通常不是 `main`。

## Mental Models

- 把可执行文件视为虚拟地址空间的初始化蓝图。
- 把 page fault 视为按需装载的正常控制流之一，不等同于程序错误。
- 把 BSS 的“文件中没有主体、内存中有零页”看成文件视图与执行视图差异。

## Anti-patterns

- **把装载描述为整文件复制**：无法解释共享、按需分页和 BSS。
- **从 section 权限直接断言进程映射**：应看 segment 与系统实际映射。
- **默认入口就是 main**：忽略动态链接器和 CRT 启动代码。

## Worked Example

对一个 ELF 同时查看 section headers、program headers 和进程 `/proc/.../maps`。把 `.text/.rodata/.data/.bss` 分别对应到 LOAD segment，核对文件大小与内存大小差异、R/W/X 权限和页对齐。首次触碰尚未驻留的数据页时发生缺页，内核从文件或零页来源建立映射；这比“loader 把 ELF 全复制进 RAM”更准确。

## Key Takeaways

1. 装载首先是地址空间与权限问题，其次才是物理内存驻留。
2. section 与 segment 必须分开理解。
3. 入口链包含内核、动态链接器和 CRT。
4. 对齐与页粒度会造成文件布局和内存布局差异。
5. 诊断装载失败要同时检查文件头、segment、解释器、依赖和实际映射。

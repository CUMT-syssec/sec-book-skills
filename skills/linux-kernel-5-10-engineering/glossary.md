# Glossary

**ABI (Application Binary Interface)** — 用户空间与内核、不同位宽或架构之间不可轻易破坏的二进制契约，包括布局、编号、对齐和调用约定。（Ch14）

**atomic context** — 不允许睡眠的执行状态，常见来源包括硬中断、软中断、关闭抢占或持有自旋锁。（Ch04, Ch05）

**atomic_t / atomic64_t** — 对整数提供原子读改写的类型；原子性不自动等于对象生命周期安全或完整内存序。（Ch05, Ch06）

**bio** — 块层描述一组块 I/O 段及完成回调的基本对象，提交后所有权遵循具体 API 契约。（Ch10）

**blk-mq** — 多队列块层框架，将软件提交队列映射到硬件调度队列和驱动 `queue_rq` 回调。（Ch10）

**BPF verifier** — 在程序装载前验证控制流、指针和辅助函数使用等安全条件的内核组件。（Ch17）

**capability** — 将传统 root 权限拆分后的权限位；检查必须结合当前凭据、命名空间和 LSM。（Ch16）

**completion** — 表示一次或多次事件完成的等待原语，由 `complete*()` 与 `wait_for_completion*()` 配对。（Ch13）

**CONFIG symbol** — Kconfig 定义的构建选择，可能改变声明、对象文件、内联 stub、模块性和运行路径。（Ch02）

**credentials (cred)** — 任务安全身份的引用计数对象；读取、准备、提交和覆盖凭据有各自所有权规则。（Ch16）

**dentry** — VFS 名称与 inode 关联的缓存对象，不等同于打开文件实例。（Ch09）

**devm / devres** — 与 device 生命周期绑定的托管资源机制；简化 probe 失败与 detach 清理，但仍需处理并发停止顺序。（Ch12）

**DMA** — 设备与内存之间的数据传输机制；地址映射、同步、方向和设备生命周期均属于契约。（Ch12）

**fault injection** — 主动让分配或 I/O 路径失败以验证回滚、资源释放和错误传播。（Ch18）

**file_operations** — VFS 将打开文件操作分派给实现的回调表，回调上下文和对象引用依操作而异。（Ch09）

**GFP flags** — 内存分配上下文与回收约束的组合；应从可睡眠性和递归风险选择，而非失败后随意切换。（Ch08）

**grace period** — RCU 中保证旧读者已离开临界区的时间边界，之后才可回收被摘除对象。（Ch06）

**hard IRQ** — 硬件中断处理上下文，不能睡眠，通常应把较长工作延后执行。（Ch04, Ch13）

**initcall** — 按级别在内核启动期间调用的初始化函数；模块构建时宏语义可能折叠为模块入口。（Ch15）

**inode** — VFS 表示文件系统对象元数据和操作的核心对象；其引用、锁和回写与 dentry/file 分离。（Ch09）

**kobject** — 设备模型/sysfs 的引用计数基础对象；释放通常由 `kobject_put()` 触发的 release 回调完成。（Ch12）

**kref** — 为内核对象封装的引用计数接口，最后一次 `kref_put()` 调用 release。（Ch06）

**KUnit** — 可与内核构建集成的单元测试框架，5.10.240 树提供 UML 运行工具和配置。（Ch18）

**Kbuild** — 决定对象如何递归编译、链接为 built-in 或 module，以及生成头文件的构建描述系统。（Ch02）

**Kconfig** — 描述配置符号、依赖、选择和菜单的语言及解析系统。（Ch02）

**kselftest** — 位于 `tools/testing/selftests`、面向运行中内核用户接口和行为的自测试集合。（Ch18）

**lockdep** — 运行时记录锁类、依赖顺序和 IRQ 安全状态，用于发现潜在死锁和错误上下文。（Ch05, Ch18）

**LSM (Linux Security Module)** — 通过安全 hook 在核心操作边界实施附加访问控制的框架。（Ch16）

**memory barrier** — 约束编译器或 CPU 可见顺序的原语；必须说明配对端和被发布状态。（Ch05）

**module reference** — 防止可卸载模块在其代码仍可能执行时被移除的引用机制。（Ch15）

**mutex** — 可睡眠的互斥锁，只能用于允许阻塞的进程上下文。（Ch04, Ch05）

**NAPI** — 网络接收的轮询机制，在 softirq 语境中限制中断压力并批量处理数据包。（Ch11, Ch13）

**net_device** — 网络接口的核心注册对象；注册、通知、数据路径、注销和命名空间迁移需协调。（Ch11）

**page fault** — 地址访问触发的内存管理事件，可能建立映射、分配页、执行文件系统 I/O 或返回错误。（Ch08）

**preemption** — 内核任务被调度切换的能力；禁用抢占会改变允许的操作和锁规则。（Ch04, Ch07）

**RCU** — 通过读侧轻量临界区、发布原语和 grace period 分离查找、删除与回收的同步方法。（Ch06）

**refcount_t** — 具有饱和与误用防护语义的引用计数类型，优先用于对象生命周期。（Ch06）

**request** — 块层调度后交给设备队列处理的请求对象，可能聚合多个 bio。（Ch10）

**runqueue (rq)** — 调度器按 CPU 维护的可运行任务和调度类状态，受严格锁与 IRQ 规则保护。（Ch07）

**seqcount / seqlock** — 写侧序列化、读侧乐观读取并在序号变化时重试的机制；不适合包含不稳定指针的裸快照。（Ch05）

**sk_buff (skb)** — 网络栈承载包数据、元数据和引用关系的核心对象，函数成功返回常伴随所有权转移。（Ch11）

**softirq** — 延后执行的原子上下文机制，不能睡眠；网络 RX/TX 和部分定时器路径使用它。（Ch04, Ch13）

**sparse** — 利用地址空间、`__user` 等注解进行语义静态检查的工具。（Ch14, Ch18）

**spinlock** — 忙等锁，用于短临界区和原子上下文；IRQ/BH 共享状态需要相应变体。（Ch04, Ch05）

**syscall** — 用户态进入内核的稳定入口，涉及架构调用约定、参数验证、凭据、安全 hook 和兼容 ABI。（Ch14, Ch16）

**task_struct** — 表示任务执行、调度、地址空间、凭据和资源关系的核心结构。（Ch07）

**tracepoint** — 具有稳定内核调用位点和动态订阅机制的观测点，探针注销后还需满足生命周期要求。（Ch17）

**uaccess** — 安全访问用户地址的 API 与注解体系；用户拷贝可能 fault、部分成功或要求特定上下文。（Ch14）

**UAPI** — 安装给用户空间使用的头文件及相关接口语义，是兼容性边界。（Ch14）

**VFS** — 在具体文件系统之上统一 path、dentry、inode、file 和操作表的抽象层。（Ch09）

**VMA (vm_area_struct)** — 描述进程虚拟地址区间、权限、映射来源和操作的内存管理对象。（Ch08）

**waitqueue** — 以条件循环组织任务睡眠与唤醒的机制；无锁活跃检查需要明确屏障配对。（Ch13）

**workqueue** — 在工作线程进程上下文执行延迟工作的基础设施；销毁对象前必须取消或排空相关 work。（Ch13）

# 第 10 章：系统级 I/O

## Core Idea

Unix 把设备、终端、管道、套接字和普通文件统一为字节序列，并通过文件描述符操作。可靠 I/O 的关键不是记住几个系统调用，而是正确处理短计数、中断、偏移共享、描述符继承以及缓冲层之间的约束。

## Frameworks Introduced

### 描述符生命周期

1. `open` 或其他创建调用返回进程描述符表中的索引。
2. 描述符表项引用打开文件表项；后者保存当前偏移和状态标志。
3. 打开文件表项再引用文件的元数据对象。
4. `fork` 复制描述符表引用，因此父子进程可共享打开文件偏移。
5. `dup2` 改变描述符引用，可实现标准输入/输出重定向。
6. 每个所有者在完成后关闭描述符；最后一个引用消失时内核释放打开状态。

### 稳健读写循环

把“请求读取 N 字节”和“本次 `read` 返回 N 字节”分开。循环处理正的短计数；`EINTR` 时重试；读到 0 表示 EOF；其他负返回是错误。写操作同样必须处理短写。

## Key Concepts

- **文件描述符**：进程局部的小整数句柄；标准输入、输出、错误通常对应 0、1、2。
- **打开文件表**：内核级对象，保存偏移、状态和引用计数；多个描述符可以指向同一项。
- **文件元数据**：`stat`/`fstat` 提供类型、权限、大小和时间等信息；目录也是包含目录项的文件类型。
- **短计数**：系统调用成功但传输量少于请求量；管道、终端和网络中很常见，普通文件也不应假设永不发生。
- **RIO**：书中封装的稳健 I/O 包，提供无缓冲定长操作和带缓冲文本读取，用循环隐藏短计数细节。
- **重定向**：用 `dup2(oldfd, newfd)` 让目标描述符引用与源描述符相同的打开文件。
- **标准 I/O**：`FILE *` 提供用户态缓冲与格式化；与底层描述符混用时必须理解缓冲和定位规则。

## Mental Models

- 描述符不是文件本身，而是“进程表中的一条引用”。
- `read`/`write` 是流式推进，返回值才是本次实际进度。
- `fork` 后“整数相同”只是表象；真正影响语义的是父子引用了同一个还是不同的打开文件表项。

## Anti-patterns

- 假设一次 `read` 或 `write` 完成全部请求。
- 忽略 `EINTR`，或把 EOF 当作错误。
- 在错误路径遗忘关闭描述符，长期服务最终耗尽描述符表。
- `fork`/`exec` 前未规划哪些描述符应继承，导致资源泄漏或权限边界扩大。
- 在同一流上无协调地混用 `stdio` 与 Unix I/O，造成缓冲、偏移或输出顺序异常。

## Code Examples

```c
ssize_t readn(int fd, void *buf, size_t n) {
    size_t left = n;
    unsigned char *p = buf;

    while (left > 0) {
        ssize_t rc = read(fd, p, left);
        if (rc > 0) {
            left -= (size_t)rc;
            p += rc;
        } else if (rc == 0) {
            break;                  /* EOF */
        } else if (errno != EINTR) {
            return -1;
        }
    }
    return (ssize_t)(n - left);
}
```

调用者仍须判断返回值是 `n`、小于 `n` 的 EOF，还是 `-1`。若 `n > SSIZE_MAX`，接口还应在调用前拒绝或分批处理。

## Reference Tables

| 层次 | 适用场景 | 必须留意 |
|---|---|---|
| Unix I/O | 描述符、套接字、重定向、精确控制 | 短计数、`errno`、生命周期 |
| RIO | 教学中的网络定长/按行读写 | 缓冲版与无缓冲版不要交叉读取同一流 |
| 标准 I/O | 格式化文本、可移植文件处理 | 用户态缓冲、刷新和线程交互 |

| 操作 | 引用关系变化 | 常见用途 |
|---|---|---|
| `open` | 新描述符 → 新打开文件项 | 打开文件 |
| `fork` | 子进程复制描述符引用 | 进程协作 |
| `dup2` | 目标描述符改指向源打开文件项 | 重定向 |
| `close` | 删除一个描述符引用 | 释放所有权 |

## Worked Example

父进程打开文件后 `fork`，父子描述符数字相同，并共同引用一个带偏移的打开文件表项。父进程先读 10 字节，子进程随后读取时通常从共享偏移 10 开始，而不是重新从 0 开始。若两者需要独立偏移，应分别打开文件，或使用显式偏移的接口并定义并发语义。

## Key Takeaways

- 所有传输循环都由返回值推进，而不是由请求长度推进。
- 画出“进程描述符表 → 打开文件表 → 文件元数据”的引用图，能解释继承、共享偏移和重定向。
- 错误路径与成功路径同样需要明确关闭责任。
- 对网络和管道使用流式思维；消息边界必须由上层协议定义。

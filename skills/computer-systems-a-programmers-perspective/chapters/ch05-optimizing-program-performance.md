# 第 5 章：优化程序性能

## Core Idea

高性能代码来自可测量的变换：消除不必要工作，减少内存依赖，暴露指令级并行，并尊重处理器的延迟、吞吐和分支预测限制。任何优化都必须保持语义并由测量验证。

## Frameworks Introduced

- **性能优化闭环**：建立基线 → 找热点 → 建立机器级模型 → 做单一变换 → 复测正确性与性能。
  - When to use：性能目标未达成或某版本发生回退时。
  - Failure mode：没有基线就“凭感觉优化”，无法区分收益、噪声和副作用。
- **CPE 模型**：用每元素周期数描述线性数据处理的稳态性能。
  - How：对不同输入规模计时，用线性拟合分离固定开销和每元素成本。
- **关键路径与吞吐界限**：循环性能由数据依赖链的延迟界限和功能单元吞吐界限共同约束。
  - How：从汇编构造数据流图，标出跨迭代依赖和可并行操作。
- **逐级变换策略**：代码移动、减少过程调用、消除不必要内存引用、循环展开、多累积变量、重新结合。
  - Why it works：从消除工作逐步转向暴露并行性，便于解释每次收益。
- **剖析驱动优化**：把优化预算放到累计耗时高且可改进的路径，而不是最复杂的函数。

## Key Concepts

- **延迟**：一项操作从输入可用到结果可用的最短时间。
- **吞吐量**：功能单元单位周期可开始或完成的操作数。
- **循环展开**：单次迭代处理多个元素，减少循环控制并增加独立操作。
- **多累积变量**：把一条循环携带依赖拆为多条独立依赖链。
- **重新结合**：在语义允许时改变运算分组，以缩短关键路径。
- **寄存器溢出**：活跃值超过寄存器容量后被写回内存。
- **分支预测错误处罚**：错误推测被清空并重取正确路径的周期成本。

## Mental Models

- 把循环看成数据流图：最慢的依赖环决定速度上限。
- 优先消除每次迭代都重复但结果不变的工作。
- 当算术已足够快时，继续优化往往受加载、存储或分支限制。

## Anti-patterns

- **破坏可读性却没有测量收益**：增加维护成本，性能可能不变甚至变差。
- **假设编译器能跨越所有别名或副作用**：函数调用、指针别名和内存写会阻止合法优化。
- **无限循环展开**：代码膨胀、寄存器溢出和指令缓存压力会反噬。
- **用微基准替代真实工作负载**：缓存状态、输入分布和调用上下文不同会导致错误结论。

## Code Examples

```c
double sum(const double *a, size_t n) {
    double acc0 = 0.0, acc1 = 0.0;
    size_t i = 0;
    for (; i + 1 < n; i += 2) {
        acc0 += a[i];
        acc1 += a[i + 1];
    }
    for (; i < n; ++i) acc0 += a[i];
    return acc0 + acc1;
}
```

- **What it demonstrates**：2×1 展开配合两个累积变量，减少循环开销并拆分跨迭代依赖；浮点重新分组可能改变舍入结果，必须确认语义容许。

## Reference Tables

| 现象 | 优先变换 | 主要风险 |
|---|---|---|
| 循环内重复计算 | 代码移动 | 值是否真是不变量 |
| 每元素函数调用 | 内联/替换 | 副作用、代码体积 |
| 累积值反复读写内存 | 局部累积变量 | 别名语义 |
| 循环控制占比高 | 循环展开 | 尾部处理、膨胀 |
| 单一依赖链限制 | 多累积变量 | 寄存器压力、舍入 |
| 不可预测分支 | 条件传送或无分支形式 | 两侧计算代价 |

## Worked Example

优化数组归约时，先测得基线 CPE；把长度查询移出循环；把累积值保存在局部变量而不是每次写回目标指针；再观察汇编的数据依赖链。若单一累积变量受加法延迟限制，采用两个独立累积变量。最后分别检查整数溢出或浮点舍入语义、尾部元素处理以及不同数组规模下的 CPE，只有全部通过才接受变换。

## Key Takeaways

1. 优化从可复现基线和热点证据开始。
2. 编译器必须保守处理别名和副作用；源代码结构会限制优化空间。
3. 关键路径决定延迟界限，功能单元决定吞吐界限。
4. 展开与多累积变量能暴露并行性，但存在寄存器和数值语义代价。
5. 最终结果必须同时通过正确性、真实负载性能和可维护性检查。

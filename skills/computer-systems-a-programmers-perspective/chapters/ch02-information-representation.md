# 第 2 章：信息的表示和处理

## Core Idea

机器中的整数、浮点数、字符和指针最终都是有限宽度的位向量。理解编码、范围、转换和模运算，才能预测 C 程序在边界值附近的真实行为。

## Frameworks Introduced

- **位向量模型**：需要推理机器数据时，先固定字长 `w`，再解释位模式。
  - How：标出最高位、权重、允许范围以及运算是否按 `2^w` 取模。
- **无符号与补码双重解释**：同一 `w` 位模式可表示无符号数或补码整数。
  - How：无符号权重全为正；补码最高位权重为 `-2^(w-1)`。
  - Failure mode：在比较或算术表达式中发生隐式无符号转换，负数变成巨大正数。
- **模运算模型**：解释整数溢出时，把机器加法和乘法看作模 `2^w` 运算。
  - When to use：哈希、环形计数器、溢出检测和边界分析。
- **IEEE 754 分段解释**：把浮点位模式拆成符号、阶码和尾数。
  - How：先分类为零、非规格化数、规格化数、无穷或 NaN，再计算数值。

## Key Concepts

- **字节序**：多字节对象在内存中的字节排列，分小端和大端。
- **十六进制**：每个十六进制数字对应 4 位，适合观察位模式。
- **补码**：现代机器表示有符号整数的主流编码。
- **符号扩展**：扩大补码字长时复制最高有效位，保持数值不变。
- **截断**：缩短字长时保留低位，相当于对 `2^k` 取模后再解释。
- **舍入**：把实数映射到有限浮点集合的规则；默认通常是向偶数舍入。
- **NaN**：表示未定义或不可表示的浮点结果，不参与普通全序比较。

## Mental Models

- 先问“位模式是什么”，再问“当前类型如何解释它”。
- 把整数溢出看作绕环，而不是数学整数无限延伸。
- 把浮点数看作近似编码：范围与精度是分开的资源。

## Anti-patterns

- **混用有符号和无符号值**：比较、循环和长度检查可能反转语义。
- **假设有符号溢出可移植**：C 中有符号溢出是未定义行为，编译器可据此优化。
- **用浮点相等判断一般计算结果**：舍入误差会让数学上相等的路径得到不同位模式。
- **把移位当作可移植除法**：对负数的右移以及超字长移位需检查语言与平台规则。

## Code Examples

```c
#include <stddef.h>

int index_in_range(int i, size_t n) {
    return i >= 0 && (size_t)i < n;
}
```

- **What it demonstrates**：先排除负数，再转换为无符号长度类型；避免 `i < n` 触发隐式转换后把负数视为巨大正数。

## Reference Tables

| 编码 | `w` 位范围 | 关键公式 |
|---|---:|---|
| 无符号 | `0` 到 `2^w-1` | `Σ x_i 2^i` |
| 补码 | `-2^(w-1)` 到 `2^(w-1)-1` | `-x_(w-1)2^(w-1) + Σ x_i2^i` |
| 浮点规格化数 | 有限范围内 | `(-1)^s × M × 2^E` |
| 浮点特殊值 | 零、无穷、NaN | 由阶码与尾数字段组合判定 |

## Worked Example

以 4 位模式 `1101` 为例：无符号解释为 `13`；补码解释为 `-8+4+1=-3`。若 C 表达式把 `-3` 与无符号 `1` 比较，`-3` 会先转换成对应的无符号值 `13`（在 4 位模型中），于是 `-3 < 1` 的直觉不再成立。排查此类错误时，应写出操作数类型、提升规则和最终位宽，而不是只看十进制打印结果。

## Key Takeaways

1. 任何数值推理都必须显式固定类型和字长。
2. 有限整数运算的核心是模 `2^w`；数学等式不能直接照搬。
3. 比较长度前先处理负数，避免隐式无符号转换。
4. 浮点数提供巨大动态范围，但精度不均匀且运算通常不满足结合律。
5. 观察底层表示时用十六进制和逐字节输出，而不是依赖强制类型别名。

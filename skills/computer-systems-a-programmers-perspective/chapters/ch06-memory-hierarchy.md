# 第 6 章：存储器层次结构

## Core Idea

存储系统通过层次化缓存调和“快、小、贵”和“慢、大、便宜”的矛盾。程序性能取决于访问模式是否具有时间局部性和空间局部性，而不只取决于数据总量。

## Frameworks Introduced

- **局部性分析**：评价数据结构或循环时，分别检查时间局部性、空间局部性和工作集大小。
  - How：列出访问顺序、步长、重复距离以及内外循环对应的内存维度。
- **缓存地址分解**：把地址拆为标记 `t`、组索引 `s` 和块偏移 `b`。
  - When to use：手工判断命中、冲突和替换时。
- **缓存未命中分类**：强制、冲突和容量未命中分别对应首次访问、映射竞争和工作集过大。
  - Why it works：不同未命中需要不同优化；增加容量不能解决所有冲突。
- **存储器山**：用工作集大小和访问步长二维测量读吞吐，观察层次结构边界。
- **缓存友好重排**：让最内层循环沿连续内存方向移动，并尽量复用已加载块。

## Key Concepts

- **SRAM/DRAM**：前者更快更贵，常用于缓存；后者更密集，常用于主存。
- **块/缓存行**：相邻层之间传送和缓存的固定大小数据单元。
- **命中率/未命中率**：访问在当前层找到或未找到的比例。
- **组相联度**：一个组可容纳的缓存行数量。
- **写回/直写**：写只更新本层并延迟下传，或同时写下一层。
- **写分配/非写分配**：写未命中时是否先把块取入缓存。
- **抖动**：少数映射位置反复替换导致高冲突未命中。

## Mental Models

- 把每一层都看成下一层的缓存，包括主存对磁盘的缓存。
- 访问成本是“命中时间 + 未命中概率 × 未命中处罚”的组合。
- 对行主序数组，最内层索引应尽量对应连续元素。

## Anti-patterns

- **只看算法复杂度**：两个同为 `O(n)` 的实现可因步长和缓存行为相差巨大。
- **把更大缓存视为万能答案**：冲突、不良布局和带宽瓶颈可能仍存在。
- **随机追逐指针却期待预取有效**：缺少空间局部性和可预测地址序列。
- **过早针对单一缓存参数硬编码**：牺牲可移植性且可能在新机器上退化。

## Code Examples

```c
for (size_t i = 0; i < rows; ++i)
    for (size_t j = 0; j < cols; ++j)
        sum += a[i][j];
```

- **What it demonstrates**：对 C 的行主序二维数组按行扫描，使最内层访问连续，通常优于按列跨大步长扫描。

## Reference Tables

| 未命中类型 | 识别特征 | 常用改进 |
|---|---|---|
| 强制 | 第一次访问块 | 预取、顺序访问；不能完全消除 |
| 冲突 | 容量足够但映射到同一组 | 改布局/步长、提高相联度 |
| 容量 | 活跃工作集超过缓存 | 分块、缩小工作集 |

| 写策略 | 优点 | 代价 |
|---|---|---|
| 直写 | 下一层总是最新，控制简单 | 写流量大 |
| 写回 | 降低层间写流量 | 需要脏位与替换写回 |
| 写分配 | 利用后续局部性 | 写未命中需先取块 |
| 非写分配 | 避免一次性写污染 | 后续读写可能再次未命中 |

## Worked Example

比较矩阵按行和按列求和。两者算术操作相同，但按行访问地址连续，一个缓存行取入后可消费多个元素；按列访问的步长约为一整行，可能每次只用一个元素并快速驱逐缓存行。验证时固定编译选项，扫多个矩阵尺寸；当工作集跨过 L1、L2、L3 和主存容量时，吞吐会形成“山脊”和“台阶”。

## Key Takeaways

1. 优化访问模式前先画出地址序列和工作集。
2. 强制、冲突和容量未命中必须分别诊断。
3. 连续访问和适度复用通常比猜测具体替换策略更可移植。
4. 分块把工作集限制在较高层缓存，是处理大数组的通用方法。
5. 用跨尺寸、跨步长基准验证，而不是只测一个输入。

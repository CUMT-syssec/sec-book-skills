# 第 11 章：网络编程

## Core Idea

网络应用建立在客户端—服务器事务之上：客户端发出请求，服务器处理并返回响应。套接字把网络端点纳入文件描述符模型，但网络增加了命名、字节序、部分传输、异步故障、并发和不可信输入等约束。

## Frameworks Introduced

### 从名字到已连接套接字

1. 用主机名和服务名调用 `getaddrinfo`，得到可尝试的地址结构链表。
2. 对每个候选地址创建 `socket`，再由客户端 `connect`，或由服务器 `bind`。
3. 服务器 `listen` 后循环 `accept`，每次得到一个已连接描述符；监听描述符继续接收新连接。
4. 在字节流上运行应用层协议，循环读写并验证长度、格式和状态。
5. 关闭已连接描述符，释放地址信息；服务器通常保持监听描述符直到退出。

### 请求生命周期

用“解析 → 验证 → 执行 → 编码响应 → 关闭/复用”分解服务器路径。每一步都应规定输入上限、错误响应、资源所有权和超时。书中的 TINY Web 服务器用于解释机制，不是可直接暴露到生产网络的安全服务器。

## Key Concepts

- **客户端—服务器模型**：角色由一次事务决定；同一主机上的程序也可通过网络接口通信。
- **IP 地址与域名**：IP 标识网络接口，DNS 把域名解析为地址；应用不应假定只有 IPv4 或只有一个结果。
- **端口与连接**：端口标识主机上的服务端点；TCP 连接由本地和远端地址/端口共同区分。
- **套接字接口**：`socket`、`connect`、`bind`、`listen`、`accept` 将协议状态映射成描述符操作。
- **网络字节序**：多字节整数按网络约定编码；优先使用地址解析和转换接口，避免手工拼接结构。
- **HTTP 事务**：请求行、首部、可选正文与响应状态、首部、正文组成应用层语义；必须由协议解析器确定边界。
- **动态内容**：书中通过 CGI 展示服务器与子进程协作；真实系统还要处理输入验证、环境隔离、超时和资源限制。

## Mental Models

- 把 TCP 看成可靠、有序的字节流，而不是保留每次 `write` 边界的消息队列。
- 把 `getaddrinfo` 返回值看成“候选方案列表”，逐个尝试而不是只取第一项。
- 把监听套接字看成接待台，把 `accept` 返回的已连接套接字看成一次会话。

## Anti-patterns

- 假设域名只解析到一个 IPv4 地址，或把地址硬编码进程序。
- 假设一次接收正好得到一条完整请求。
- 将客户端提供的路径直接拼接到文件系统路径，产生目录穿越风险。
- 无输入长度、超时、并发数和响应大小限制。
- 把书中教学服务器当作生产安全基线；它没有覆盖 TLS、完整 HTTP 语义与系统化加固。

## Code Examples

下面展示客户端对 `getaddrinfo` 候选逐个连接的核心结构：

```c
struct addrinfo hints = {0}, *list = NULL, *p;
hints.ai_socktype = SOCK_STREAM;
hints.ai_flags = AI_NUMERICSERV;

int rc = getaddrinfo(host, service, &hints, &list);
if (rc != 0) return -1;

int fd = -1;
for (p = list; p != NULL; p = p->ai_next) {
    fd = socket(p->ai_family, p->ai_socktype, p->ai_protocol);
    if (fd < 0) continue;
    if (connect(fd, p->ai_addr, p->ai_addrlen) == 0) break;
    close(fd);
    fd = -1;
}
freeaddrinfo(list);
return fd;
```

生产代码还需定义连接超时、取消、日志脱敏、地址选择策略和错误分类。

## Reference Tables

| 服务器描述符 | 创建路径 | 职责 | 生命周期 |
|---|---|---|---|
| 监听描述符 | `socket → bind → listen` | 排队等待连接 | 通常贯穿服务器进程 |
| 已连接描述符 | `accept` | 与一个客户端收发字节 | 单次会话或协议复用期 |

| 层次 | 关注对象 | 常见故障 |
|---|---|---|
| 名称解析 | 主机名、服务名、地址列表 | 无结果、临时解析失败 |
| 连接建立 | 地址族、端口、监听队列 | 拒绝、超时、路由失败 |
| 传输 | 有序字节流 | 短读写、对端关闭、阻塞 |
| 应用协议 | 边界、状态、语义 | 格式错误、超限、不可信输入 |

## Worked Example

浏览器请求静态对象时，先解析服务器名并建立 TCP 连接，再发送 HTTP 请求。服务器从监听描述符 `accept` 得到会话描述符，解析请求行和首部，验证方法与路径，将文件元数据转换为状态和首部，循环发送正文，最后按协议关闭或复用连接。任何一步失败都应转成明确错误路径，且不能让客户端控制任意本地路径。

## Key Takeaways

- 名称、端点、连接、字节流和应用消息是不同层次。
- 对候选地址逐一尝试，对所有网络 I/O 处理短计数和中途关闭。
- 先定义协议边界与资源上限，再编写解析器和业务逻辑。
- TINY 适合理解端到端机制，不代表生产级正确性或安全性。

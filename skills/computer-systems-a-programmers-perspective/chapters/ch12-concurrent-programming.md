# 第 12 章：并发编程

## Core Idea

并发程序让多个逻辑流在时间上重叠。进程、I/O 多路复用和线程提供不同的共享与调度模型；真正困难的是共享状态的正确性、进度保证和资源管理。判断并发代码时必须考虑所有允许的交错，而不是只看一次成功运行。

## Frameworks Introduced

### 并发模型选择

- 需要强隔离、可独立失败时优先考虑进程；代价是通信与切换更重。
- 单线程需要管理大量 I/O 会话、且每个步骤不阻塞时，可用 I/O 多路复用显式驱动状态机。
- 需要低成本共享内存和自然表达独立任务时可用线程，但必须同步共享变量并管理线程生命周期。

### 共享状态推理

1. 列出线程共享、线程局部和只读对象。
2. 为每个共享可变对象指定唯一同步协议。
3. 将必须不可分割的读—改—写序列定义为临界区。
4. 用互斥锁或信号量保护不变量，而不是保护某一行代码。
5. 检查安全性、活性、锁顺序、取消/退出路径和资源回收。

## Key Concepts

- **线程上下文**：每个线程有独立栈、寄存器和线程 ID，但共享进程代码、全局数据、堆与打开文件。
- **逻辑并发与并行**：并发描述生命周期重叠；并行要求同时在多个执行单元上运行。
- **竞态**：结果依赖不可控的执行顺序；即使单次机器指令看似简单，语言层读改写也可能非原子。
- **信号量 P/V**：`P` 等待并减一，`V` 加一并唤醒等待者；二元信号量可作互斥锁，计数信号量可表示资源数量。
- **生产者—消费者**：用 `mutex` 保护缓冲区不变量，用 `slots` 和 `items` 分别计数空槽与已有项。
- **线程安全与可重入**：线程安全函数可在多线程调用；可重入函数不依赖共享可变状态，通常更容易组合。
- **死锁**：一组线程循环等待彼此持有的资源；统一锁顺序是常用预防策略。
- **Amdahl 定律**：整体加速受不可并行部分限制；增加线程不能消除串行瓶颈和同步开销。

## Mental Models

- 把调度器看成可在任意允许点切换执行流的对手。
- 把锁看成不变量的所有权令牌，而不是让代码“变快或变安全”的装饰。
- 把每个线程的创建、分离/回收、取消和退出画成生命周期图。

## Anti-patterns

- 用 `volatile` 代替同步；它不建立所需的互斥和跨线程顺序。
- 因为测试运行多次未失败，就断言不存在竞态。
- 持锁执行可能阻塞的网络、磁盘或用户回调，扩大延迟和死锁面。
- 在不同路径以不同顺序获取多把锁。
- 忘记回收可结合线程，或让分离线程引用已结束栈帧中的对象。
- 仅按 CPU 核数增加线程，不测串行比例、争用、缓存和调度开销。

## Code Examples

有界缓冲区的信号量次序应先获取容量/项目令牌，再进入互斥区：

```text
producer(x):
    P(slots)
    P(mutex)
    insert x
    V(mutex)
    V(items)

consumer():
    P(items)
    P(mutex)
    x = remove()
    V(mutex)
    V(slots)
    return x
```

不要在持有 `mutex` 时等待 `slots` 或 `items`，否则可能阻止能改变该条件的另一方进入缓冲区。

## Reference Tables

| 模型 | 默认共享 | 优势 | 主要风险 |
|---|---|---|---|
| 进程 | 很少，显式 IPC | 隔离和故障边界清晰 | 通信、复制与管理成本 |
| I/O 多路复用 | 单线程状态 | 无数据竞态，连接规模大 | 状态机复杂，阻塞调用拖住全局 |
| 线程 | 地址空间与描述符 | 通信自然、开销较低 | 竞态、死锁、生命周期错误 |

| 症状 | 可能原因 | 证据手段 |
|---|---|---|
| 偶发错误结果 | 数据竞态或次序假设 | ThreadSanitizer、事件日志、最小交错 |
| 全部停住 | 死锁或遗漏唤醒 | 线程栈、锁等待图 |
| 线程越多越慢 | 争用、串行段、缓存抖动 | 分阶段计时、扩展性曲线 |
| 资源持续增长 | 线程/连接未回收 | 生命周期计数与泄漏检测 |

## Worked Example

两个线程执行 `counter++`。该表达式通常包含读取、加一、写回。若两者都先读到 10，各自计算 11，再先后写回，最终结果是 11 而不是 12。给单次写操作加“看似原子”的假设无法修复问题；必须用互斥锁保护完整的读—改—写不变量，或选用语义合适的原子操作。

## Key Takeaways

- 先选共享模型，再设计同步；不要先创建线程再补锁。
- 为共享可变状态写出不变量、所有者和同步协议。
- 正确性包括没有竞态，也包括无死锁、可终止和可回收。
- 通过压力测试、竞态检测器和可观测事件验证，但任何有限测试都不能穷尽所有交错。
- 性能优化应测串行比例和争用，不能只比较线程数量。

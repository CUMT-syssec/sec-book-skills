# 第 8 章：异常控制流

## Core Idea

异常控制流（ECF）统一解释从硬件异常、系统调用和上下文切换，到进程、信号和非本地跳转的控制变化。正确程序必须显式处理异步事件、资源回收和可能的执行顺序。

## Frameworks Introduced

- **异常分类**：按原因和恢复点区分中断、陷阱、故障和终止。
  - When to use：判断事件是异步设备输入、主动系统调用、可恢复错误还是不可恢复错误时。
- **进程三抽象**：独立逻辑控制流、私有地址空间、并发执行假象。
- **进程生命周期**：`fork` 创建、`execve` 替换映像、`waitpid` 回收、`exit` 终止。
  - How：同时跟踪父子两个返回路径、打开描述符和僵尸回收责任。
- **信号状态模型**：发送、未决、阻塞和接收是不同状态；普通信号通常不排队。
  - How：处理共享状态时先阻塞相关信号，更新状态后再恢复掩码。
- **异步安全规则**：信号处理器只调用异步信号安全函数，保存/恢复 `errno`，共享标志使用 `volatile sig_atomic_t`。

## Key Concepts

- **异常表**：异常号到内核处理程序地址的映射。
- **上下文切换**：内核保存一个进程状态并恢复另一个进程状态。
- **僵尸进程**：已终止但尚未由父进程回收退出状态的子进程。
- **进程组**：shell 作业控制和信号广播的基本单位。
- **信号掩码**：当前阻塞的信号集合。
- **竞态**：结果依赖不可控事件顺序的缺陷。
- **非本地跳转**：`setjmp`/`longjmp` 跨越普通调用返回规则改变控制流。

## Mental Models

- 把 `fork` 看成从一个控制点分裂出两个独立控制流，而不是“调用一次返回一次”。
- 把信号处理器看成随时插入主程序的受限中断上下文。
- 资源所有权随 `fork` 复制、随 `execve` 保留部分内核状态、随退出需要回收。

## Anti-patterns

- **父进程不回收子进程**：长期服务会积累僵尸。
- **在信号处理器中调用 `printf`、`malloc` 等非安全函数**：可能死锁或破坏库内部状态。
- **用 `pause` 等待条件却不先阻塞信号**：检查条件与休眠之间存在丢失唤醒竞态。
- **假设信号逐个排队**：相同普通信号多次到达可能只留下一个未决状态。
- **用 `longjmp` 绕过资源清理**：锁、堆对象和文件状态可能泄漏或失衡。

## Code Examples

```c
pid_t pid = fork();
if (pid == 0) {
    execl("/bin/echo", "echo", "child", (char *)0);
    _exit(127);
}
if (pid > 0) {
    int status;
    while (waitpid(pid, &status, 0) < 0 && errno == EINTR) {}
}
```

- **What it demonstrates**：子进程替换程序映像，失败时使用 `_exit`；父进程处理被信号中断的等待并回收子进程。

## Worked Example

一个 shell 启动前台作业时，先 `fork`；子进程设置进程组并 `execve` 目标程序；父进程记录作业并等待。若用户按 Ctrl-C，终端把信号发给前台进程组，而不是只发给 shell。`SIGCHLD` 处理器应循环调用非阻塞 `waitpid` 回收所有已终止子进程；更新作业表时，主流程和处理器必须用信号掩码保护临界区，避免“子进程先退出、作业后登记”的竞态。

## Key Takeaways

1. ECF 是硬件、内核和应用共同使用的控制机制。
2. `fork`、`execve`、`waitpid` 分别负责创建、替换和回收，不可相互替代。
3. 信号处理器能力受限，复杂工作应转移到普通控制流。
4. 用信号掩码和原子状态消除检查—执行竞态。
5. 进程树、进程组和描述符所有权必须一起设计。

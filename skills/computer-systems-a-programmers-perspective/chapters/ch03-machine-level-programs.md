# 第 3 章：程序的机器级表示

## Core Idea

阅读编译器生成的 x86-64 汇编，是理解 C 语言控制结构、调用约定、数据布局、指针和安全边界的桥梁。目标不是手写大量汇编，而是能从机器代码反推程序行为。

## Frameworks Introduced

- **编译器输出实验法**：需要理解某个 C 构造的实现时，构造最小函数并观察 `-Og` 汇编与反汇编。
  - How：改变一个源代码因素 → 重新编译 → 对比指令、寄存器和控制流。
- **调用约定模型**：分析函数调用时，按参数传递、返回地址、保存责任、栈帧和返回值分解。
  - When to use：ABI 不匹配、崩溃回溯、FFI、逆向和栈破坏诊断。
- **地址计算模型**：把有效地址看成 `base + index*scale + displacement`。
  - How：先还原地址，再根据指令后缀确定访问宽度和符号扩展。
- **控制流图**：把条件码、跳转和条件传送还原为基本块与边。
  - Failure mode：逐行翻译汇编却不先识别循环、分支合流和函数边界。
- **纵深缓冲区防护**：栈随机化、栈保护值和不可执行内存共同降低溢出利用风险。

## Key Concepts

- **ISA**：软件可见的指令、寄存器、数据类型和状态规范。
- **寄存器**：处理器中保存地址、参数、临时值和状态的快速存储。
- **条件码**：算术结果产生的零、符号、进位和溢出等状态。
- **栈帧**：函数调用期间保存返回信息、局部量和溢出参数的区域。
- **过程调用约定**：调用者和被调用者对寄存器、栈与返回值的协议。
- **数据对齐**：让对象地址满足其类型或 ABI 的边界要求。
- **缓冲区溢出**：越界写覆盖控制数据或邻接对象的缺陷。

## Mental Models

- 把汇编视为编译器生成的结构化模式，不要视为随机指令列表。
- 当一条指令同时含地址和数据宽度时，先分开回答“访问哪里”和“访问多少”。
- 调试崩溃时沿“调用约定的不变量”检查：栈指针、返回地址、保存寄存器和对齐。

## Anti-patterns

- **只在高优化级别学习汇编**：重排和消除会掩盖源程序结构；初始分析宜用 `-Og`。
- **把寄存器名当成固定变量名**：寄存器的角色会随控制流和优化变化。
- **忽略写入宽度**：低位写、零扩展和符号扩展会产生不同结果。
- **把栈保护当成内存安全**：防护降低利用概率，但不修复越界访问本身。

## Code Examples

```sh
gcc -Og -S sample.c -o sample.s
gcc -Og -c sample.c -o sample.o
objdump -d sample.o
```

- **What it demonstrates**：从可读汇编、可重定位目标到机器字节逐层观察编译结果。

## Reference Tables

| 分析对象 | 优先问题 | 常用证据 |
|---|---|---|
| 数据传送 | 宽度、扩展、源与目的 | 指令后缀、寄存器子名 |
| 条件分支 | 哪些条件码被读取 | 比较指令、跳转条件 |
| 函数调用 | 参数、保存责任、栈对齐 | ABI、序言/尾声、调用点 |
| 数组/结构 | 步长、偏移、填充 | 有效地址、类型布局 |
| 崩溃 | 越界写破坏了什么 | 栈、返回地址、保护值 |

## Worked Example

分析一个 `x < y ? y-x : x-y` 函数：先确认参数寄存器和返回寄存器；找到比较指令产生的条件码；观察编译器选择条件跳转还是条件传送；再检查两条减法的操作数顺序。若优化后没有明显分支，应把条件传送理解为“先计算候选值，再按条件选择”，而不是误判源程序没有条件逻辑。

## Key Takeaways

1. 从最小实验和 `-Og` 开始建立 C 到汇编的映射。
2. 先重建控制流图，再解释每条指令。
3. 调用约定是跨函数、跨语言和调试工具共同依赖的协议。
4. 指针在机器级就是地址；类型信息主要存在于编译阶段。
5. 所有越界访问都应修复，安全缓解机制不是正确性证明。

# 第 4 章：处理器体系结构

## Core Idea

用简化的 Y86-64 指令集把 ISA 语义逐步实现为顺序处理器，再通过流水线提升吞吐量。处理器设计的核心是在保持顺序可见行为的同时管理时序、依赖、冒险和异常。

## Frameworks Introduced

- **ISA 与实现分离**：评价处理器时，先区分软件可见语义和内部实现。
  - When to use：比较不同微架构为何能执行同一机器代码时。
- **五阶段指令模型**：取指、译码、执行、访存、写回，并在末端更新下一 PC。
  - How：对每类指令写出各阶段的输入、组合逻辑、状态更新和异常状态。
- **HCL 控制逻辑**：用布尔与字级选择表达式描述数据通路控制，而不是直接画门级电路。
- **流水线吞吐模型**：将组合逻辑分段并插入寄存器，让多条指令的不同阶段重叠。
  - Why it works：缩短时钟关键路径并提高单位时间完成的指令数。
  - Failure mode：分段不均、寄存器开销和反馈依赖会限制收益。
- **冒险处理决策**：数据前递优先，无法前递时暂停；错误路径用气泡取消；异常必须保持精确顺序。

## Key Concepts

- **程序员可见状态**：寄存器、条件码、PC、内存和状态码。
- **组合逻辑**：输出只由当前输入决定，不保存状态。
- **时钟寄存器**：在时钟边沿提交新状态。
- **关键路径**：决定最小时钟周期的最长组合延迟链。
- **数据冒险**：指令读取尚未产生或写回的值。
- **控制冒险**：下一条指令地址依赖尚未确定的分支或返回。
- **精确异常**：异常前指令已提交，异常及之后指令没有可见副作用。

## Mental Models

- 把单周期处理器看成正确性基线，把流水线看成对时间安排的等价变换。
- 每次增加并行阶段，都问“跨阶段需要保存什么状态”和“错误推测如何撤销”。
- 性能由吞吐量、延迟与关键路径共同决定，不能只数阶段数量。

## Anti-patterns

- **把流水线阶段数等同于加速比**：寄存器延迟、冒险和不均衡会吞噬收益。
- **只暂停不前递**：虽然可能正确，但会产生不必要的性能损失。
- **在异常指令之后提交状态**：破坏精确异常和顺序语义。
- **混淆组合信号与时序状态**：会产生竞态、错误反馈或不可实现的控制逻辑。

## Code Examples

```text
fetch -> decode -> execute -> memory -> write_back

if value_available_in_later_stage:
    forward(value)
elif load_use_dependency:
    stall_fetch_and_decode()
    bubble_execute()
```

- **What it demonstrates**：流水线控制不是一条通用规则，而是依赖类型驱动的前递、暂停与气泡组合。

## Reference Tables

| 阶段 | 主要工作 | 典型状态/结果 |
|---|---|---|
| Fetch | 取指并预测下一 PC | 指令字节、`valP` |
| Decode | 读寄存器 | `valA`、`valB` |
| Execute | ALU 计算与条件判断 | `valE`、条件结果 |
| Memory | 读写数据存储器 | `valM` |
| Write back | 更新寄存器文件 | 架构状态 |

## Worked Example

考虑“从内存加载到寄存器，下一条立即使用该寄存器”。加载值直到访存阶段结束才可用，下一条指令在更早的执行阶段已经需要它，因此普通前递来不及。正确策略是暂停取指和译码一个周期，并向执行阶段插入气泡；随后把加载结果前递给消费者。若只前递而不暂停，消费者会读取旧值；若一律暂停多周期，行为正确但吞吐量低。

## Key Takeaways

1. 先建立顺序实现作为可验证的语义基线，再做流水化变换。
2. 组合逻辑计算候选值，时钟边沿提交架构状态。
3. 数据前递减少停顿，但加载—使用依赖仍需气泡。
4. 分支预测提升吞吐量，错误预测必须取消错误路径副作用。
5. 异常、返回和冒险控制必须共同维护顺序可见行为。

# 第 1 章：计算机系统漫游

## Core Idea

把一个最小的 `hello` 程序当作探针，沿着源代码、编译系统、处理器、存储层次、操作系统和网络逐层追踪。程序的正确性与性能不是语言层面的孤立属性，而是整个系统协作的结果。

## Frameworks Introduced

- **程序生命周期**：需要解释“程序为何这样运行”时，从源文件到进程退出逐阶段定位。
  - When to use：编译失败、启动慢、输出异常、I/O 阻塞或跨主机运行出现问题时。
  - How：源程序 → 预处理 → 编译 → 汇编 → 链接 → 加载 → 取指执行 → I/O → 退出。
  - Why it works：每一步都有清晰的输入、输出和责任边界，便于把模糊的“程序坏了”缩小成一个系统阶段。
- **存储器层次结构**：分析数据访问成本时，把寄存器、缓存、主存和持久存储看成逐层变大、变慢、变便宜的体系。
  - How：先判断工作集位于哪一层，再分析命中、未命中和层间复制。
- **操作系统三大抽象**：用进程抽象处理器与设备，用虚拟内存抽象主存与磁盘，用文件抽象 I/O 设备。
  - When to use：区分应用可见接口与内核/硬件实现时。
- **Amdahl 定律**：评估局部优化对整体的上限。
  - How：若可优化部分占比为 `a`、加速倍数为 `k`，整体加速比为 `1 / ((1-a) + a/k)`。
  - Failure mode：只优化最醒目的局部，却忽略它在总时间中的占比。

## Key Concepts

- **位与上下文**：同一位模式只有结合类型、指令和协议才有含义。
- **编译系统**：预处理器、编译器、汇编器和链接器组成的转换链。
- **总线**：在系统组件之间传送字节块的共享通路。
- **缓存**：用更小、更快的存储保存下一层数据的副本。
- **进程**：操作系统提供的“程序独占处理器和地址空间”的抽象。
- **线程**：进程内共享代码和数据、拥有独立控制流的执行单元。
- **虚拟内存**：为进程提供一致、私有地址空间的硬件—内核协作机制。
- **文件**：Unix 对磁盘、终端、网络等 I/O 对象的统一字节序列抽象。

## Mental Models

- 把“执行程序”想成字节在编译链、存储层次和设备之间不断搬运。
- 当性能不符合直觉时，先问“数据在哪里、移动了几次”，再看算术指令。
- 当接口看起来很简单时，主动寻找它隐藏的系统抽象与资源所有权。

## Anti-patterns

- **把高级语言当成完整机器模型**：会遗漏溢出、缓存、链接、虚拟内存和系统调用造成的行为。
- **用局部加速比冒充整体收益**：违反 Amdahl 定律，常导致优化目标选择错误。
- **把并发等同于并行**：并发描述多个活动重叠；并行强调同时执行以加速。

## Code Examples

```c
#include <stdio.h>

int main(void) {
    printf("hello, world\n");
    return 0;
}
```

- **What it demonstrates**：一个极小程序仍依赖编译、链接、加载、虚拟内存、缓存、系统调用和设备输出。

## Reference Tables

| 层面 | 应用看到的对象 | 主要实现者 | 常见诊断问题 |
|---|---|---|---|
| 编译 | 可执行文件 | 编译器、汇编器、链接器 | 符号、ABI、目标文件 |
| 执行 | 指令流 | CPU、缓存、主存 | 分支、访存、局部性 |
| 操作系统 | 进程、虚拟内存、文件 | 内核与硬件 | 隔离、映射、I/O |
| 网络 | 字节流或报文 | 协议栈与适配器 | 延迟、连接、字节序 |

## Worked Example

追踪 `hello`：编辑器把字符编码写入 `hello.c`；编译系统生成可执行目标文件；shell 创建进程并加载代码与数据；CPU 从入口开始取指，缓存和主存提供指令与字符串；`printf` 最终通过系统级 I/O 把字节送到终端。若“没有输出”，应按这条链检查：程序是否成功链接、是否启动、是否到达输出调用、缓冲区是否刷新、描述符是否指向预期终端，而不是只盯着 `printf` 一行。

## Key Takeaways

1. 用跨层追踪替代单层猜测。
2. 性能问题首先是数据移动问题，其次才是计算问题。
3. 操作系统抽象让应用可移植，但不会消除底层代价。
4. 先用 Amdahl 定律判断优化上限，再投入实现成本。
5. 抽象是控制复杂度的工具，也是诊断时需要主动拆开的边界。
